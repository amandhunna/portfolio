Rules. Skills. Context.

We keep handing AI our codebases and expecting it to just know what to do.

It doesn't.

It has no clue about your spacing system, your token naming, or why a button is 48px and not 44.

So I wrote it all down — at the project level — and built a full portfolio + design system in few hours.

Here's what changed everything:

---

Rules are the guardrails.

Thirteen of them. An 8pt spacing grid. 60-30-10 color distribution. A 1.25x type scale. Mobile-first layout. Rem units. Accessibility minimums.

Token names like spacing/sm and color/accent/base are identical in code and Figma.

The AI doesn't improvise spacing or pick random colors. It reads the rules and follows them.

---

Skills tell the AI which hat to wear.

A lightweight table maps tasks to behaviors:

-> "Senior Frontend Engineer" for architecture decisions
-> "Code Connect" for wiring Figma components to React
-> "Implement Design" for pixel-perfect screens

Instead of one generic mode for everything, the AI switches approach based on the job.

Right tool. Right moment.

---

Context is the briefing doc.

One folder. docs/ai/. It holds everything:

-> Who the project is for
-> What's already built
-> What's still missing
-> Which conventions apply

Every conversation starts from the same baseline. No scattered READMEs. No tribal knowledge.

One command: "Read CONTEXT.md and docs/ai/ before you touch anything."

---

Why bother?

Because when you give AI a playbook, a role sheet, and a brief — it stops producing generic code.

It starts producing code that belongs in your system.

It respects your grid.
It uses your tokens.
It picks the right component.

The back-and-forth drops.
The rework drops.
You ship more in one afternoon than you normally would in a week.

---

If you want AI to actually accelerate your product work, spend an hour writing rules, skills, and context at the project level.

The prompt is five seconds: "Read CONTEXT.md first."

The payoff compounds with every session.
